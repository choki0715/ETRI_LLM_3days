# 지시 문장 모음

## 한 문장씩 쌓는다 (회차마다 지시 하나 → 플레이 → 커밋)

| 회차 | 지시 한 문장 | 플레이로 확인 | 커밋 메시지 예 |
|---|---|---|---|
| 1 | index.html에 캔버스를 만들고 패들을 그려서 ← → 키로 움직이게 해줘 | 패들이 화면 밖으로 안 나간다 | 패들 이동 |
| 2 | 공을 하나 띄워서 네 벽에 맞으면 튕기게 해줘 | 네 벽에서 모두 튕긴다 | 공과 벽 |
| 3 | 공이 패들에 맞으면 튕기고, 바닥에 떨어지면 다시 시작하게 해줘 | 패들 양 끝에서도 튕긴다 | 패들 충돌 |
| 4 | 벽돌 5줄을 깔고, 공에 맞은 벽돌은 사라지게 해줘 | 맞은 벽돌만 사라진다 | 벽돌 |
| 5 | 점수와 목숨 3개를 표시하고, 게임오버와 클리어 화면을 넣어줘 | 목숨 0이면 멈추고 다시 시작된다 | 점수 · 목숨 · 종료 화면 |
| 6 | (선택) 패들에 맞은 위치에 따라 튕기는 각도를 바꿔줘 | 끝에 맞으면 비스듬히 튕긴다 | 패들 각도 |

```bash
git add -A && git commit -m "패들 이동"      # 잘 돌면 바로 저장
```

## 되돌리는 법

| 명령 | 언제 |
|---|---|
| `git diff` | 방금 무엇이 바뀌었나 |
| `git restore .` | 커밋 이후 바뀐 것을 버린다 — 마지막으로 잘 돌던 상태로 |
| `git log --oneline` | 저장 지점 목록 |
| `git revert <커밋>` | 이미 커밋한 변경을 되돌리는 새 커밋 |

Claude Code 안에서는 Esc 두 번으로 체크포인트를 되감을 수 있습니다. 파일 변경만 되돌리고, git을 대신하지는 않습니다.

## 한 번에 시키면 안 되나? (10분 비교 실험)

1~6회차를 끝낸 뒤에 합니다 — 한 문장씩 만든 게임(`~/breakout`, 이하 B)이 있어야 비교할 수 있습니다.

```bash
mkdir ~/breakout-once && cd ~/breakout-once && git init && claude
```

1. `아타리 벽돌깨기 게임 만들어줘` → 돌려 본다 → `git add -A && git commit -m "한 번에"`
2. `패들 모서리에서 공이 파고드는 것만 고쳐줘`
3. `git diff --stat` — 몇 줄이 바뀌었나
4. B(`~/breakout`)에도 같은 문장을 시키고 `git diff --stat`으로 바뀐 줄 수를 비교한다

만드는 것은 한 번에 될 수 있습니다. 차이는 **고칠 때** 납니다.

## 실패를 다음 지시로 바꾸기 — 네 가지를 넣는다

| 칸 | 예 |
|---|---|
| 현상 | 공이 패들 안으로 파고들어 떨린다 |
| 기대 | 모서리에 맞아도 위로 튕겨야 한다 |
| 재현 | 패들 오른쪽 끝으로 공을 받으면 |
| 범위 | 패들 충돌 처리만 고치고, 다른 기능은 건드리지 마 |

```
패들 오른쪽 끝으로 공을 받으면 공이 패들 안으로 파고들어 떨려. 모서리에 맞아도 위로 튕겨야 해.
패들 충돌 처리 부분만 확인해서 고치고, 다른 기능은 건드리지 마.
```

내 실패로 채워 보기:

```
(재현) ______________ 하면 (현상) ______________ 돼. (기대) ______________ 해야 해.
(범위) ______________ 부분만 고치고, 다른 기능은 건드리지 마.
```

## 먼저 끝난 사람에게 — 여전히 한 문장씩

- 벽돌에서 떨어지는 아이템을 받으면 패들이 30초 동안 길어지게 해줘
- 벽돌을 다 깨면 다음 레벨로 — 벽돌 배치를 바꾸고 공을 10% 빠르게 해줘
- 최고 점수를 브라우저에 저장해서 다시 열어도 남게 해줘
- 벽돌 · 패들 · 벽에 맞을 때 각각 다른 짧은 소리를 Web Audio로 내줘
- 휴대폰에서 손가락으로 패들을 움직이게 해줘

기능이 늘수록 체크리스트 8번 · 2번이 다시 깨지기 쉽습니다.
