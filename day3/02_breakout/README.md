# 실습 · 바이브 코딩 — 아타리 벽돌깨기 (2세션 · 80분)

코드를 안 보는 것이 아니라, **검증 지점을 결과로 옮기는** 연습입니다. 한 문장 → 플레이 → 하나만 고친다 → 커밋.

| 파일 | 쓰임 |
|---|---|
| `CLAUDE.md.example` | 내 환경의 상수 10줄 — 복사해서 고쳐 쓴다 |
| `checklist.md` | 플레이 테스트 8개 + 회차 기록표 — 인쇄해서 쓴다 |
| `prompts.md` | 회차별 한 문장 · 되돌리기 · 한 번에 시키기 비교 · 실패를 지시로 바꾸는 틀 · 확장 과제 |
| `playtest.py` | (선택) 자동 플레이 테스트 — 체크리스트 중 코드로 볼 수 있는 것을 대신 본다 |
| `solution/index.html` | 강사 참고 답안 — 막힌 사람에게 플레이 화면만 보여 준다 |

명령은 [day3 README의 경로 약속](../README.md#경로-약속)(`$DAY3` · `$PY`)을 먼저 쳐 둔 터미널에서 실행합니다.

| 순서 | 할 일 | 시간 |
|---|---|---|
| 1 | 프로젝트 세우기 · CLAUDE.md 10줄 · 첫 커밋 | 10분 |
| 2 | 1~6회차 — 한 문장 → 플레이 → 체크리스트 → 커밋 | 50분 |
| 3 | 한 번에 시키기 비교 실험 | 10분 |
| 4 | 실패 하나를 "현상 · 기대 · 재현 · 범위" 지시로 고치기 | 10분 |

## 1. 프로젝트 세우기 (10분)

```bash
mkdir ~/breakout && cd ~/breakout && git init
cp $DAY3/02_breakout/CLAUDE.md.example CLAUDE.md      # 내 환경에 맞게 고친다 — 10줄 이내
```

**자동 플레이 테스트를 쓸 사람은 지금** CLAUDE.md에 아래 한 줄을 더합니다. 게임을 만들기 전에 넣어야 처음부터 이 모양으로 만들어집니다.

```
- 테스트용으로 게임 상태를 window.game 에 둔다: paddle{x}, ball{x,y,vx,vy,stuck}, bricks[{x,y,w,h,alive}], score, lives, state(ready·play·over·clear). 스페이스바로 시작 · 재시작
```

CLAUDE.md 점검 — 10줄 이내인가 · 한 달 뒤에도 참인가 · "잘", "적당히"가 없는가 · 옆 사람이 내 환경을 그릴 수 있는가.

```bash
git add -A && git commit -m "CLAUDE.md"
claude                                                 # Shift+Tab 으로 Accept edits 모드
```

## 2. 1~6회차 — 한 문장씩 쌓는다 (50분)

[prompts.md](prompts.md)의 회차별 한 문장을 하나씩 넣습니다. 회차마다:

1. 지시 한 문장을 넣는다
2. 브라우저에서 `index.html`을 열어 직접 한 판 한다
3. [checklist.md](checklist.md)의 8개를 다시 해 보고 기록표에 한 줄
4. 잘 돌면 커밋 (`git add -A && git commit -m "패들 이동"`)
5. 나빠졌으면 다음 지시로 덮지 말고 **되돌린 뒤** 지시를 바꿔 다시 — [prompts.md의 되돌리는 법](prompts.md#되돌리는-법)

### 자동 플레이 테스트 (선택)

1번에서 `window.game` 줄을 넣었다면, 회차가 끝날 때마다 사람이 보던 체크 1~7을 코드가 대신 봅니다. 줄을 안 넣었으면 콘솔 에러 · 캔버스 · 키 입력 · 창 크기만 봅니다.

```bash
$PY $DAY3/02_breakout/playtest.py ~/breakout/index.html     # 화면을 playtest_*.png로 남긴다
```

이 한 줄이 오후 하네스의 예고편입니다 — **사람이 눈으로 보던 검증을 코드가 볼 수 있게 꺼내 놓는 것.**
자동 테스트가 통과해도 직접 한 판은 합니다. 손맛(속도 · 각도)은 코드가 못 봅니다.

## 3. 한 번에 시키기 비교 실험 (10분)

2번에서 한 문장씩 만든 게임이 있어야 비교할 수 있습니다. 새 폴더에서 한 번에 시켜 보고, **같은 수정**을 양쪽에 시켜 바뀐 줄 수를 비교합니다 — [prompts.md의 비교 실험](prompts.md#한-번에-시키면-안-되나-10분-비교-실험).

## 4. 실패를 다음 지시로 바꾸기 (10분)

체크리스트에서 실패한 항목 하나를 골라 "현상 · 기대 · 재현 · 범위" 네 칸을 채운 지시로 고칩니다 — [prompts.md의 틀](prompts.md#실패를-다음-지시로-바꾸기--네-가지를-넣는다). 고친 뒤 체크리스트 8개를 다시 합니다.

먼저 끝난 사람은 [prompts.md의 확장 과제](prompts.md#먼저-끝난-사람에게--여전히-한-문장씩)로 — 여전히 한 문장씩.

## 강사 메모

- 보는 것은 산출물 품질이 아니라 **사이클**입니다 — 한 문장씩 넣는가, 회차마다 커밋하는가, 나빠지면 되돌리는가. 큰 지시를 한 번에 넣는 사람을 잡아 줍니다.
- 강사 답안(`solution/index.html`)으로 자동 플레이 테스트를 돌린 결과 — 통과 12 · 실패 0. 패들 클램프를 빼고 벽돌 충돌의 `break`를 지운 고장판에서는 1번(패들 이탈)과 3번(모서리에서 10개 사라짐)이 실패로 잡혔습니다. "깬 벽돌 N개"는 실시간으로 도는 게임이라 실행마다 달라집니다(판정에는 영향 없음).
