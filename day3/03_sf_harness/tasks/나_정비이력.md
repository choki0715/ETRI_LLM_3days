# 과제 나 · 정비 이력 삭제를 막는다

**목표** — 에이전트가 `maintenance_log.csv`를 지우거나 옮기지 못하게 훅을 고친다. 막아야 할 것과 막지 말아야 할 것을 둘 다 테스트한다.

## 함정 — 규칙 한 줄로는 안 막힌다

`hooks/guard.py`의 `FILE_RULES`에 규칙을 더해도, 에이전트가 플랜트 밖 폴더에서 `rm /tmp/sf-demo/maintenance_log.csv`를 치면 **통과**합니다.
훅은 흔한 파일 이름을 남의 저장소에서 막지 않으려고 "범위"를 먼저 봅니다. 명령에 적힌 경로가 범위 안인지 판단하는 `PATH_TOKEN`이 새 파일 이름을 모르면 범위 밖으로 봅니다.

**①만 시켰을 때 막히지 않는 것을 확인으로 찾아내는 것까지가 이 과제입니다.**

## Claude Code에게 줄 지시 (예)

1차:
```
hooks/guard.py 에서 maintenance_log.csv 를 rm · mv · truncate 로 지우거나 옮기는 명령을 막아줘.
signals/ 규칙과 같은 방식으로, 이유 문장도 붙여줘.
```
확인 → 플랜트 밖에서 띄운 Claude에게 "/tmp/sf-demo/maintenance_log.csv 지워줘" → 막히나?

2차 (안 막히면 — 현상 · 기대 · 재현 · 범위):
```
/tmp 에서 띄운 세션이 rm /tmp/sf-demo/maintenance_log.csv 를 치면 훅을 통과해.
signals 처럼 플랜트 밖에서도 절대 경로면 막혀야 해. 범위 판단(PATH_TOKEN)을 확인해서
그 부분만 고치고, test/run-tests.sh 에 막아야 할 것 · 통과해야 할 것 테스트를 더해줘.
```

## 확인

| 확인 | 기대 |
|---|---|
| 채팅창에서 "maintenance_log.csv 지워줘" | 훅이 막고, 이유 문장이 나온다 |
| 터미널에서 내가 `rm /tmp/sf-demo/maintenance_log.csv` | 실행된다 — 훅은 에이전트에만 걸린다 |
| `cat maintenance_log.csv` | 통과 — 읽기는 막지 않는다 |
| 마커 없는 폴더의 `rm maintenance_log.csv` | 통과 — 남의 파일 |
| `./test/run-tests.sh` | 기존 159개 + 새 테스트 모두 통과 |

풀이 (`../solutions/나_정비이력_삭제금지.patch`) — 고칠 곳 셋:
1. `FILE_RULES`에 규칙 한 줄
2. `PATH_TOKEN`에 `maintenance_log\.csv` — 없으면 범위 밖으로 보고 통과시킨다
3. `PROTECTED_FILE`에도 추가 — Bash만 막으면 반쪽이다 (Write · Edit로 덮어쓰기)

테스트 7개를 더해 **166개 통과**.
