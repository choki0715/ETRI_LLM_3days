# 과제 다 · 새 사실을 하나 센다

**목표** — "창 전반 대비 후반 평균 변화율"을 `sf-signals`가 세게 하고, analyze 스킬이 그 값을 근거로 쓰게 한다.

왜 필요한가 — `TREND_PER_HOUR`(기울기)는 꾸준한 증가에 강하지만, 어느 순간 **계단처럼 뛴** 변화는 덜 드러납니다. 전반 평균과 후반 평균을 비교하면 보입니다.

## 고칠 곳 셋

| 파일 | 무엇을 |
|---|---|
| `bin/sf-signals` | 센서마다 `<설비>.<센서>.HALF_CHANGE_PCT: +12.34` 한 줄 출력 |
| `skills/analyze/SKILL.md` | 키 설명 표에 한 줄 + 언제 소견 근거로 쓰는지 |
| `test/run-tests.sh` | 고정 데이터에서 값이 맞는지 확인 |

## Claude Code에게 줄 지시 (예)

```
bin/sf-signals 에서 센서마다 창 전반 평균 대비 후반 평균의 변화율(%)을
<설비>.<센서>.HALF_CHANGE_PCT 키로 TREND_PER_HOUR 다음 줄에 출력해줘.
샘플이 4개 미만이거나 전반 평균이 0이면 none. 형식은 TREND_PER_HOUR 처럼 부호 붙은 소수 둘째 자리.
그다음 skills/analyze/SKILL.md 키 표에 설명 한 줄을 더하고, test/run-tests.sh 에 확인을 하나 더해줘.
다른 출력 줄은 바꾸지 마 — 스킬이 그 줄들을 읽는다.
```

## 확인

```bash
$SF/sf-demo-data --fresh
$SF/sf-signals | grep HALF_CHANGE_PCT
./test/run-tests.sh
```

기대값 (원본 데이터, 시작 시각 2026-09-16T14:00:00):

```
CNC-02.vibration.HALF_CHANGE_PCT: +136.73
CNC-02.temperature.HALF_CHANGE_PCT: +15.20
CNC-01.current.HALF_CHANGE_PCT: -0.01
```

`/sf-harness:run` 소견서에 새 키가 근거로 인용되는지 봅니다.

## 생각할 것

- 스크립트에 넣었기 때문에 **테스트할 수 있습니다.** 스킬에 "전반 · 후반 평균을 비교해라"라고만 썼다면 LLM이 매번 다르게 셌을 겁니다 — Day 2 "셀 수 있는 일은 코드가 한다".
- 출력 줄 하나를 더하는 것은 안전하지만, 기존 줄의 모양을 바꾸면 스킬이 깨집니다. 그래서 `SF_SIGNALS_PROTO` 번호가 있습니다.
