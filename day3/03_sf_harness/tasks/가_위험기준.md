# 과제 가 · 위험 기준을 바꾼다

**목표** — "CRIT 연속 몇 샘플이면 위험인가"를 바꾸고, 같은 데이터에서 소견과 제안이 달라지는 것을 본다.

## 고칠 곳

기준은 `sf-harness/skills/analyze/SKILL.md`의 판정 표에 있습니다 (decide가 아니라 **analyze**).

```
| **위험**   | `CRIT_STREAK ≥ 3`. …
| **재확인** | … 또는 `CRIT_STREAK 1~2` |
```

두 줄이 짝입니다. 위험 기준만 바꾸고 재확인 범위를 그대로 두면 3~4가 어디에도 속하지 않는 구멍이 생깁니다.

## 숫자를 무엇으로 바꾸나

기본 데이터에서 CNC-02 진동은 처음부터 CRIT 연속 **12**입니다. 3 → 5로 바꾸면 결과가 그대로라 차이가 안 보입니다.

| 바꾼 값 | 처음 상태에서 CNC-02 | 보이는 차이 |
|---|---|---|
| 3 → 5 | 여전히 위험 (12 ≥ 5) | 처음 상태에선 차이 없음. `sf-collect --minutes 27` 뒤 CNC-02 **온도**의 CRIT 연속이 4일 때 소견 문구가 달라진다 |
| 3 → 15 | 재확인 (12 < 15) | stop 제안 대신 recheck 제안 — 차이가 바로 보인다 |

## Claude Code에게 줄 지시 (예)

```
skills/analyze/SKILL.md 판정 표에서 위험 기준을 CRIT_STREAK ≥ 15 로 바꾸고,
재확인 범위도 빈틈이 없게 1~14 로 맞춰줘. 이 표 말고는 건드리지 마.
```

## 확인

```bash
$SF/sf-demo-data --fresh
```
`/sf-harness:run` → CNC-02 소견이 **재확인**, 제안이 **recheck**인가. 바꾸기 전 결과(실습 2 기록)와 나란히 놓습니다.

## 생각할 것

- 스킬(마크다운)은 테스트 스크립트로 검증하기 어렵습니다 — 출력이 매번 다르니까. 그래서 sf-harness는 **셀 수 있는 것은 스크립트로** 뺐습니다.
- 정말 15가 맞을까요? 기준을 바꾸는 것은 안전 판단입니다. 누가 정해야 하나요? (그래서 `thresholds.csv` 수정은 훅이 막습니다.)
